# Sonic Display V865.10 – Dance Rig Regression Compatibility

## Ursache

Das in V545 getestete Overlay `applyAvatarRigMotion(rigTargets.current, debugMotion)` existiert im aktuellen V865-Rig nicht mehr. Der aktuell gültige Aufruf lautet `applyAvatarRigMotion(rigTargets.current, footworkV839.motion, ...)`. Vorher sind die bestehenden Schutzstufen V545, V587, V596, V665, V666, V759, V684, V685 und V839 aktiv. Die V545-Assertion prüfte einen nicht vorhandenen String mittels `indexOf(...)` und schlug fehl.

Weitere ältere Tests suchten noch nach dem ungefilterten Gruppen-Footwork `naturalFootworkV524.slots[i]`, während in V865 die abschließende V839-Footwork-Stufe mit `finalFootworkV839.slots[i]` verwendet wird.

## Änderungen

- `tests/v545-natural-dance-motion-regression.cjs`: explizite Prüfungen für alle existierenden Pipeline-Stationen; fehlende Strings sind Fehler (kein irreführender `indexOf() === -1`-Vergleich); exakt eine Foot-IK-Aktualisierung.
- `tests/v587-expressive-dance-footwork-regression.cjs`: gleiche gesicherte Pfadprüfung und aktuelle Gruppenverbindung.
- `tests/v524-natural-full-body-dance-regression.cjs`: V524 -> V684 -> V839 -> V494, einschließlich finalem Slot-Output.
- `tests/v485-natural-dance-motion-studio-regression.cjs` und `tests/v486-advanced-dance-footwork-regression.cjs`: bei den Gruppenprüfungen nun die tatsächlich zuständige `GroupDancersV326SceneV492.tsx`; ursprüngliche root-offset Durchleitung bleibt überprüft.

Kein produktiver Code, kein `package.json`, keine GLB-Datei oder andere Build-Konfiguration wird verändert.

Der Installer wurde nicht unter Windows ausgeführt. Außerdem wurden keine GLB-Files für einen GPU-/Browser-Test geladen; die V545-Prüfung meldete 0 lokale GLB-Fixtures.

## Installation

ZIP in einen **eigenen Ordner** entpacken. Im entpackten Ordner PowerShell starten und ausführen:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-V865.10.ps1 -ProjectPath "C:\Users\Christian\git\sonic-display"
```

Der Installer verifiziert zunächst die SHA256-Prüfsummen, sichert alle fünf lokalen Originaldateien, installiert die Korrekturen, prüft sie erneut und startet sieben gezielte Funktionstests. Bei einem Fehler versucht er, die Dateien aus dem Backup automatisch wiederherzustellen.

Danach im Projektverzeichnis: `npm run test:smoke:v665`, `npx tsc --noEmit`, `npm run build`.
