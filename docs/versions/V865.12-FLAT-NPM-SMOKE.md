# Sonic Display V865.12 – Windows npm PATH / Smoke-Chain Hotfix

## Diagnose

`node` wird innerhalb von `npm run test:v649` nach einer tiefen Kette aus `test:smoke:v665 → v664 → ... → v649` in Windows `cmd.exe` nicht mehr gefunden, obwohl es aus PowerShell aufrufbar ist. Die wahrscheinliche Ursache ist ein überlanger `PATH`: Jede rekursive `npm run`-Ebene fügt zusätzliche `node_modules/.bin`-Pfade hinzu. `cmd.exe` hat eine deutlich niedrigere Längegrenze als PowerShell. Der Fehler liegt **nicht** im V649-Kontrollzentrum; ein direkter V649-Test bestand.

## Lösung ohne Verlust der historischen Qualitätschecks

Das neue Skript `scripts/run-npm-chain-flat-v86512.cjs` liest die bestehenden npm-Skripte aus `package.json`. Reine `npm run a && npm run b`-Ketten werden rekursiv in einzelne Schritte aufgelöst und exakt in ihrer ursprünglichen Reihenfolge über eigenständige, kurze npm-Prozesse ausgeführt. Wiederholte Tests bleiben erhalten; Fehler beenden die Kette sofort. Sonstige npm-Skripte werden unverändert ausgeführt. Der `PATH` für Kinder wird zusätzlich von doppelten Einträgen bereinigt.

**Die alten Skripte `test:smoke:v665`, `check:release`, `prebuild`, `check:fast` und `build` bleiben unverändert.** Es gibt neue alternative Skripte, damit alte Coverage-Assertions und bestehende CI-Konfigurationen nicht kaputtgehen.

### Windows-Befehle

```
cd C:\Users\Christian\git\sonic-display
npm run test:v86512:flat
npm run test:smoke:v665:flat
npm run test:smoke:v671:flat
npm run check:release:flat
npm run build:flat
```

Nur die benötigte Suite ausführen; `check:release:flat` kann wegen seiner großen historischen Testabdeckung lange dauern. `build:flat` führt die komplette bisherige `prebuild`-Kette aus und ruft **nur nach erfolgreichem Abschluss** die echte lokale Next.js-CLI (`next build`) auf, ohne `prebuild` doppelt zu starten. Es ist keine Produktionsprüfung deaktiviert.

Zum Anzeigen aller Tests ohne Ausführung:

```
node scripts/run-npm-chain-flat-v86512.cjs test:smoke:v665 --plan
node scripts/run-npm-chain-flat-v86512.cjs check:release --plan
```

Ein direkter Aufruf `npm run test:v649` ist weiterhin möglich. Der bisherige `npm run test:smoke:v665` verschachtelt dagegen die npm-Prozesse weiter und ist nicht die empfohlene Windows-Variante.

### Wenn `node` sogar in einer frischen CMD nicht verfügbar ist

```
where.exe node
cmd /d /c "where node && node -v"
(Get-Command node.exe).Source
$env:Path.Length
npm config get script-shell
```

Dann ist Node möglicherweise nur in PowerShell, nicht aber in `cmd.exe` erreichbar; die Node-Installationsdirectory muss auch auf dem Windows-System-PATH liegen. Eine neue PowerShell nach Änderungen öffnen.
