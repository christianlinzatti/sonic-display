# V389.2 – Ably browser build hotfix

## Build error
`ably/build/modular/index.mjs` fails to parse in Next.js 15.5.27 / Webpack at `super(...args)` even when using `ably/modular`.

## Fix
- Removed `import("ably/modular")` (and all runtime SDK imports) from `useStageContentV330`.
- The browser loads Ably's official prebuilt JavaScript SDK `https://cdn.ably.com/lib/ably.min-2.js` **only if** stage-content realtime is enabled. Loading uses a shared promise, a 12s timeout and error cleanup.
- Browser creates `new Ably.Realtime({authUrl:"/api/stage-content/realtime-token",authMethod:"GET"})`, subscribes to `stage-message` and closes on unmount. The API key remains server-side. Existing local-only SSE fallback is unchanged.
- **Network dependency:** Browsers must be allowed to load `https://cdn.ably.com`. With network/CSP restrictions, remote push won't connect; adapt CSP `script-src` if a restrictive CSP is configured. No Ably runtime source is included in the Next.js Webpack bundle.
- This hotfix also retains the V389.1 Windows case-collision fixes.

## Validate on Windows

```powershell
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue

```
