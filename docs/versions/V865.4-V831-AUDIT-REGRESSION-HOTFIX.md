# V865.4 - V831 Audit regression test fix

## Fehler

Der bisherige Test V831 erwartete bei `v831-production-gate.cjs --audit` immer einen Exitcode ungleich 0. Sind Next.js und TypeScript lokal installiert und ist das Projekt fuer einen Build bereit, ist jedoch **Exitcode 0** fuer den Audit korrekt. Das bedeutet `ready-to-test`, nicht eine produktive Freigabe. Auf Windows mit installierten Abhaengigkeiten entstand dadurch die Fehlermeldung `Expected actual to be strictly unequal to: 0`.

## Korrektur

Nur `tests/v831-production-build-stabilization-regression.cjs` wurde angepasst. Tests pruefen jetzt beide Zustaende der Audit-Schnittstelle explizit, insbesondere mit simuliertem installierten Next.js/TypeScript in einem temporaeren Projekt:

- `ready-to-test` -> Exitcode `0`, `productionReleased === false`, `stages === []`.
- `blocked` -> Exitcode `1`, ebenfalls keine Produktionsfreigabe.
- `--audit` fuehrt weder `check:release` noch `typecheck` noch den echten Next.js-Build aus.
- Sicherheitsflags wie `--skip` bleiben unzulaessig.
- Der echte Produktions-Gate-Code wurde **nicht** abgeschwaecht oder geaendert.

## Nachweis (Node.js in dieser Umgebung)

- V831: 48 Regressionstestgruppen PASS.
- V830, V832, V841-V850, V865 und ausgewaehlte historische Tests: PASS.
- `npm run check:syntax`, `npm run check:architecture`, `npm run check:lockfile:v752`: PASS.
- Gesamt-`npm run typecheck`, Produktions-`npm run build`: **nicht erfolgreich nachgewiesen**; hier fehlen installierte Next.js-/React-Pakete.
- Windows-PowerShell-Installer kann hier nicht live getestet werden. Er prueft Projektversion, SHA256 und testet V831 nach dem Kopieren.
