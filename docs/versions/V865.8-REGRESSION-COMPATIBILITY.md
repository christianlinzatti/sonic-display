# Sonic Display V865.8 – Kameraregie-/Regression-Hotfix

## Ursache

Die Regression V682 prüfte den letzten `guardAutomaticCameraV351(...)`-Aufruf nur gegen V747 bzw. V792, obwohl die Kamerakette nun bis V848 weitergeführt wird. Die Schutzprüfung wird in `StageCameraDirectorV289.tsx` weiterhin nach V848 ausgeführt. Es war eine veraltete Test-Erwartung, keine gewünschte Änderung am Produktiv-Code.

V633, V655 und V747 enthielten dieselbe überholte Annahme. Die aktualisierten Tests verifizieren die tatsächliche Reihenfolge der Kamerakomposition bis V848 und verlangen, dass `stageFramed` durch den finalen V351-Lyrics-/Bildschutz läuft.

Ein zusätzlicher Probelauf zeigte sechs weitere falsch veraltete Testannahmen bzw. einen isolierten Testkontext:
- V647: bestehender LED-Wall-Shader wird heute über V647 -> V812 -> V821 -> V842 zusammengesetzt. Die vollständige Kette wird geprüft.
- V649: die historische Smoke-Kette wird im expliziten `check:release` geprüft; `prebuild` bleibt beim schnellen Gate.
- V651: die test-only-V649-Typdeklaration ist durch `tsconfig.json`-Ausschluss des gesamten `tests`-Ordners statt durch einen einzelnen Dateinamen ausgeschlossen.
- V656 und V680: `prebuild` hat inzwischen zusätzliche Versionstests vor `check:fast`; der Test erzwingt weiterhin das schnelle Gate und prüft auf fehlende Build-Rekursion.
- V676: der isolierte Node.js-VM-Loader stellt `TextEncoder` bereit, wie es im Browser vorhanden ist.

**Keine Produktivdateien, keine Paketversion, keine Vercel-Konfiguration und keine Funktion wurden verändert.** Es wurden ausschließlich die 10 oben beschriebenen Regressionstestdateien modernisiert.

## Installation

1. ZIP in einen eigenen Ordner entpacken.
2. PowerShell in diesem Ordner öffnen.
3. Ausführen:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-V865.8.ps1 -ProjectPath "C:\Users\Christian\git\sonic-display"
```

Der Installer prüft SHA256, legt eine Sicherung im temporären Windows-Verzeichnis an, installiert die zehn Testdateien und führt die Tests aus. Die PowerShell-Ausführung wurde unter Windows in dieser Arbeitsumgebung nicht getestet.

## Nachkontrolle

```powershell
cd C:\Users\Christian\git\sonic-display
npm run test:v682
npm run test:v682:types
npx tsc --noEmit
npm run build
```

Kein Projekt-/Datenbank-/Spotify-Zustand wird durch die Installation zurückgesetzt.
